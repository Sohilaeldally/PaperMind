# PaperMind 📄🤖

A specialized **Retrieval-Augmented Generation (RAG)** system for understanding and answering questions about AI/ML research papers. Upload a paper, and PaperMind parses it, understands its academic structure, and lets you ask natural-language questions grounded in the paper's actual content.

> Built as a deep dive into RAG systems end-to-end: document ingestion, structure-aware chunking, vector search, and LLM-grounded generation — with a full-stack implementation (FastAPI + React).

---

## ✨ Features

- **Multi-format upload** — PDF, DOCX, and TXT support
- **Structure-aware chunking** — detects academic sections (Abstract, Introduction, Methodology, Results, Conclusion...) via font analysis (PDF), Word heading styles (DOCX), and regex pattern matching, with automatic fallback to fixed-size chunking when no structure is detected
- **Semantic search** — powered by `pgvector` cosine similarity over multilingual sentence embeddings
- **Grounded Q&A (RAG)** — answers are generated by an LLM strictly from retrieved context, with source sections cited
- **Multi-document support** — upload multiple papers and scope questions to a specific one
- **Background processing** — uploads return instantly; parsing, chunking, and embedding run asynchronously with live status polling in the UI
- **Multilingual** — supports both English and Arabic queries

## 🏗️ Architecture

The backend follows a **Service / Repository** pattern for separation of concerns:

```
API Layer (FastAPI routers)
        ↓
Service Layer (business logic: parsing, chunking, embedding, search, generation)
        ↓
Repository Layer (database access only)
        ↓
PostgreSQL + pgvector
```

### Document Processing Pipeline

```
Upload → Parse → Detect Structure → Refine Sections → Chunk → Embed → Ready
```

1. **Parse** — extract raw text from the uploaded file
2. **Detect Structure** — attempt structure detection in order of reliability:
   - DOCX: Word heading styles
   - PDF: font size / boldness analysis
   - Fallback: regex-based section header matching
3. **Refine Sections** — clean whitespace, merge sections that are too short to carry meaning on their own
4. **Chunk** — sections within size limits are kept whole; oversized sections are split with fixed-size + overlap chunking
5. **Embed** — each chunk is embedded and stored with its section metadata in `pgvector`

All processing runs as a **background task**, so the upload request returns immediately while the frontend polls document status until it reaches `completed` or `failed`.

### Retrieval-Augmented Generation

```
Question → Embed query → Vector similarity search (pgvector) → Top-K chunks
         → LLM (Groq) generates answer grounded in retrieved chunks → Answer + Sources
```

## 🚀 Getting Started

### Prerequisites

- Python 3.11+
- Node.js
- PostgreSQL with the [`pgvector`](https://github.com/pgvector/pgvector) extension installed
- A free [Groq API key](https://console.groq.com)

### 1. Database Setup

```bash
psql -U postgres
CREATE DATABASE papermind;
\c papermind
CREATE EXTENSION vector;
```

Run the schema:

```bash
psql -U postgres -d papermind -f backend/database/schema.sql
```

### 2. Backend Setup

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate       # Windows
# source .venv/bin/activate  # macOS/Linux

pip install -r requirements.txt
```

Create a `.env` file in `backend/`:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=papermind
DB_USER=postgres
DB_PASSWORD=your_password
GROQ_API_KEY=your_groq_api_key
```

Run the server:

```bash
uvicorn main:app --reload
```

API docs available at: `http://127.0.0.1:8000/docs`

### 3. Frontend Setup

```bash
cd frontend
npm install
npm run dev
```

App available at: `http://localhost:5173`

## 📡 API Overview

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/documents/upload` | Upload a document; processing starts in the background |
| `GET` | `/documents/` | List all uploaded documents with status |
| `GET` | `/documents/{id}` | Get details and status for a single document |
| `POST` | `/search/` | Semantic search over document chunks |
| `POST` | `/search/ask` | Ask a question — returns an LLM-generated answer with cited sources |

Full interactive documentation is available via Swagger UI at `/docs` once the backend is running.
